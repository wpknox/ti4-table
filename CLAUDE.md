# CLAUDE.md

TI4 Table: a website for a group that plays Twilight Imperium 4 together. Three sections, phone-first:

1. **Rules**: search the Living Rules Reference plus Dane's official rulings. Works offline and installs to the home screen. *(built)*
2. **Map**: paste a map string and get a plain-English report on each seat's fairness. *(planned: `docs/plans/m2-map-analyzer.md`)*
3. **Games**: a shared log of the group's games, with stats. Friends sign in to add games. *(planned: `docs/plans/m3-games.md`)*
4. Stretch: **Ask**, plain-English rules questions answered with links to the exact paragraph. *(planned: `docs/plans/m4-ask.md`)*

The sibling repo `../ti4` is the TI4 Rules Drawer browser extension, which overlays the same rules onto ti-assistant.com. This site started from its code, so the two share search logic by copy, not by import.

Rules content comes from [tirules-search](https://github.com/wpknox/tirules-search) (the owner's fork of dangothemango/tirules, carrying Dane's rulings as `<span class="ruling">`). That content is GPL-3.0, so this repo is GPL-3.0.

## Layout

```

  index.html             App shell (one page; the client router renders sections into <main>)
  css/base.css           Tokens (colour, type), shell, shared controls, toast
  css/rules.css          Rules section
  js/app.js              Entry: registers sections, starts router, registers service worker
  js/router.js           History-API router: addSection(), navigate(), setUrl(), back()
  js/lib.js              $, esc, normChars, store (guarded localStorage), remember, toast
  js/rules/data.js       Load rules.json, number paragraphs, index, search
  js/rules/view.js       Home / results / page rendering and events
  data/rules.json        GENERATED by scripts/build-rules.mjs. Never edit by hand.
  fonts/                 Self-hosted (offline): Saira (display), Atkinson Hyperlegible Next (text). Both OFL.
  icons/                 icon.svg plus PNGs rendered from it
  sw.js                  Service worker (precache + stale-while-revalidate; skips /api/)
  manifest.webmanifest
functions/               Cloudflare Pages Functions (/api/*), from milestone 3
scripts/
  build-rules.mjs        tirules-search PHP pages -> public/data/rules.json
  serve.mjs              Dev server with SPA fallback (like Pages)
docs/plans/              One plan per milestone. Subagents work from these.
docs/research/           Findings that plans depend on (data sources, licences)
```

## Commands

```bash
node scripts/serve.mjs                          # http://localhost:8787 (service worker is off on localhost)
node scripts/build-rules.mjs ../ti4-rules/tirules   # or TIRULES_DIR=…; default ../tirules-search
```

There are no automated tests yet. Verify with Playwright against the dev server, at phone (390×844) and desktop (1280×800) sizes, in both dark and light colour schemes. The Playwright MCP may only write screenshots under the repo it was started from. Use `.playwright-mcp/` there, which is gitignored.

## Invariants (rules section)

- **One text function.** `textOf(root)` in `data.js` concatenates text nodes and skips `<style>` and the injected `.pn` paragraph-number links. The search index and the on-page highlighter both use it, which is why tapping snippet N lands on highlight N. Any change to how text is collected must apply to both. Never put visible text into a rendered page that the index didn't see: the big rule number is CSS `attr(data-num)` for exactly this reason.
- **`normChars` must stay one-for-one** (same length in and out), so normalised offsets match DOM offsets.
- **Paragraph numbers** are computed in `annotate()` from tirules' CSS counters (`content: '58.' counter(item)`, `counter-reset: item 1`). LRR paragraphs get ids like `58.3a`. Notes get `<section-slug>-<n>`. Page `<style>` tags are then removed, so they can't leak site-wide.
- **Search modes:** `phrase` (exact) first. If the phrase isn't found, `words` (paragraphs with every meaningful word, with stopwords dropped, light stemming, and aliases like AFB/TG/PN), then `some` (all but one word). The mode is put in result URLs (`&mode=`) so the page view recomputes the same matches.
- **URLs are the state.** `/rules/R_movement?q=…&mode=…&m=2#58.3`. Back/forward uses real history. `back()` falls back to `/rules` because a home-screen app has no back button.
- `replaceAll` with a non-global regex throws. `esc()` uses string arguments.
- Render errors show on the page via `textContent` (router.js), so they still appear if an HTML helper is broken.

## Design system

The frontend-design brief is TI4's own vocabulary: dark space, hex tiles, resource yellow and influence blue. Those colours mean something here and aren't decoration.

- **Tokens** live in `:root` in `base.css`. Use `--void` (background), `--hull`/`--hull-2` (surfaces), `--seam` (lines), `--star` (text), `--dust` (muted), `--influence` (links, focus, interactive), `--resource` (numbers, rulings, the brand hex), and `--tech-*` (the four tech colours, for the map). A light theme comes from `prefers-color-scheme`. Every new colour needs a light value too.
- **Type:** Saira (variable width, so use `font-stretch` 105–125% for display) for headings, numbers and controls. Atkinson Hyperlegible Next for reading text. Reading size is `--fs` (A−/A+).
- **Signature:** numbers. Rule numbers sit in a hanging gutter in expanded Saira, and the page's rule number is huge and outlined. Spend boldness there and keep everything else quiet.
- **Avoid:** all-caps labels, eyebrow text above headings, identical rounded cards everywhere, decorative gradients, entrance animations on every section.
- **Floor:** 16px gutters and no horizontal scroll at 390px, ≥44px touch targets for primary controls, visible focus, reduced-motion respected, inputs ≥16px (stops iOS zoom).
- Copy is plain and specific, in sentence case. Buttons say exactly what happens.

## Conventions

- Vanilla JS ES modules, no dependencies, no bundler. Section banners (`// ── Name ───`), short "why" comments.
- New sections register with `addSection({prefix, label, render})` in `app.js`. `render(url, main, ctx)` owns `<main>`. Check `ctx.stale()` after awaits.
- Add new static files to `PRECACHE` in `sw.js` and bump `VERSION`.
- **Sonar pass after each milestone's code lands.** The owner fixes SonarQube warnings where practical, in JS and CSS. Don't add a lint dependency to the repo: install `eslint` and `eslint-plugin-sonarjs` into the session scratchpad and run them with a throwaway flat config that uses `sonarjs.configs.recommended` over `public/js`, `scripts`, `functions` and `server`. That's the same approach as `../camp-finder/eslint.sonar.config.mjs`. Use `stylelint` the same way for CSS. Fix real findings, and note any rule you deliberately skip and why in the commit message.
- Credit upstream rules authors (dangothemango, BradleyΣ) wherever rules content is shown.
- Public repo: never commit personal names, `/Users/` paths, account IDs or secrets. `HANDOFF.md` is gitignored and holds machine-specific notes.

## Working on this repo with agents

The owner prefers an orchestrator pattern. The main session plans and reviews, and subagents implement from a plan file in `docs/plans/`. **Subagents run on lower-tier models:** pass `model: "sonnet"` for implementation and research, and `"haiku"` for mechanical lookups. Never let them inherit Opus; the owner considers it overkill for delegated work. Plans must be explicit enough for a smaller model to succeed, and the main session reviews every result before anything builds on it. A plan must be self-contained: goal, files to touch, data shapes, acceptance checks, and what's out of scope. When a session ends, update `HANDOFF.md`: what's done, what's in flight, and decisions made with their reasons.
